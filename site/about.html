The studio

A chisel doesn't add anything. It removes what's in the way.

Why the name

chisl is "chisel" with a letter cut out.

That's on purpose. The name went through the same process we put every project through: strip it down until only the necessary part is left. A chisel doesn't build anything from nothing — it takes a block that already has a shape hiding inside it and removes the material that isn't that shape.

That's closer to what web development actually is than most agency language admits. The client's business, their catalogue, their sound — the shape is already there. Our job is cutting away the friction between that and a browser: the confusing nav, the admin panel nobody can use, the page that takes four seconds to load because nothing was ever taken away.

We're small on purpose too. No layers between you and the person writing the code.

How we work

Principles, not a pitch deck

  • Content before chrome

    We build with your actual catalogue, your actual copy, your actual photos — from the first draft. Placeholder content hides problems that only show up after launch.

  • You should be able to run it

    If a project needs an admin panel, it gets one your team can actually use — not a database migration you have to email us for.

  • Fast is a feature

    Every asset, animation, and dependency earns its place. A site that loads slowly has already lost the visitor before the pitch starts.

  • Say so if something's wrong

    If a request will make the site worse, we'll say that plainly before we build it — not after you're paying for the fix.
